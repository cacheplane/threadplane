# Installation

Detailed setup guide for `injectAgent()` in your Angular application.

## Requirements

Supported Angular majors: 20, 21, and 22.

<Steps>
<Step title="Angular 20–22">
`injectAgent()` returns Angular Signals and uses the modern injection context API. Angular 20, 21, or 22 is required.
</Step>
<Step title="Node.js compatibility">
Use a Node.js version supported by the selected Angular major. Angular 22 supports Node.js ^22.22.3, ^24.15.0, or ^26.0.0. See the [Angular compatibility matrix](https://angular.dev/reference/versions).
</Step>
<Step title="LangGraph Platform">
A running LangGraph agent reachable over HTTP. Local (`langgraph dev`) or deployed (LangGraph Cloud) both work.
</Step>
</Steps>

## Install the packages

```bash
npm install @threadplane/angular @threadplane/core @threadplane/langgraph @langchain/core @langchain/langgraph-sdk
```

`@threadplane/angular` provides `provideAgent()` and `injectAgent()`. `@threadplane/langgraph` provides `createSession()`, which runs a LangGraph deployment behind the session contract that `@threadplane/core` defines. It contains no Angular code. `@threadplane/angular/chat` provides the chat UI, which works with any backend. The LangChain packages are required peers: the session uses their message types and the LangGraph SDK client.

## Peer Dependencies

`@threadplane/langgraph` declares the following peer dependencies:

| Package | Version |
|---------|---------|
| `@threadplane/core` | `0.3.7` |
| `@langchain/core` | `^1.1.33` |
| `@langchain/langgraph-sdk` | `^1.7.4` |

`@threadplane/angular` declares these:

| Package | Version |
|---------|---------|
| `@threadplane/core` | `0.3.7` |
| `@threadplane/content` | `0.3.7` |
| `@angular/core` | `^20.0.0 \|\| ^21.0.0 \|\| ^22.0.0` |

The pins on the `@threadplane` packages are exact, because the packages are released together; the other ranges are ordinary semver.

npm 7 and newer install peer dependencies automatically, so the command above is enough. It is worth knowing what arrives with it: `@threadplane/angular/chat` declares its own peers — `@threadplane/angular`, `@threadplane/core`, `@threadplane/telemetry`, `@threadplane/angular/render`, `@threadplane/a2ui`, `zod`, `@json-render/core`, `marked`, `rxjs`, and the `@angular/common`, `@angular/platform-browser`, and `@angular/router` packages. Math rendering uses KaTeX only when your application installs it and passes it to `provideChatMath()` from `@threadplane/angular/chat/math`.

## Configure the provider

Add `provideAgent()` to your application configuration and give it a `createSession` function. The agent calls that function once at start and again for each thread switch, so it always receives the thread to run on. `injectAgent()` reads the result and takes at most a typed `AgentRef`.

```typescript
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideAgent } from '@threadplane/angular';
import { createSession } from '@threadplane/langgraph';
import { environment } from '../environments/environment';

export const appConfig: ApplicationConfig = {
  providers: [
    provideAgent({
      createSession: (context) =>
        createSession({
          ...context,
          apiUrl: environment.langgraphUrl,
          assistantId: 'chat',
        }),
    }),
  ],
};
```

<Callout type="tip" title="Multiple agents in one app">
Need more than one agent instance (e.g. a sidebar chat with a different assistant)? Use hierarchical DI: declare a component-scoped `providers: [provideAgent({...})]` array in the child component, and `injectAgent()` inside that subtree resolves to that override. To keep several agents at one injector level, give each a ref from `createAgentRef()` and inject by ref.
</Callout>

## Environment setup

<Tabs>
<Tab label="Development">

For local development, configure your environment and run a LangGraph server:

```typescript
// src/environments/environment.ts
export const environment = {
  langgraphUrl: 'http://localhost:2024',
};
```

```bash
# Start LangGraph dev server
langgraph dev

# Your agent will be available at http://localhost:2024
```

</Tab>
<Tab label="Production">

For production, point to your LangGraph Cloud deployment:

```typescript
// src/environments/environment.prod.ts
export const environment = {
  langgraphUrl: 'https://your-project.langgraph.app',
};
```

</Tab>
</Tabs>

## Verify installation

Create a minimal component to verify the setup works. `injectAgent()` must be called in an injection context (a component field initializer or inside `inject()`).

```typescript
import { Component } from '@angular/core';
import { injectAgent } from '@threadplane/angular';

@Component({ selector: 'app-test', template: '' })
export class TestComponent {
  protected readonly test = injectAgent();

  constructor() {
    console.log(this.test.status()); // 'idle' — setup is correct
  }
}
```

## Troubleshooting

<Callout type="warning" title="Common issues">

**Version mismatch** -- If you see errors about missing APIs or unknown decorators, confirm your Angular version is 20, 21, or 22. Run `ng version` to check. Versions outside this range are not supported.

**CORS errors** -- If the browser console shows `Access-Control-Allow-Origin` errors, your LangGraph server is not configured for cross-origin requests. The LangGraph dev server allows all origins by default. For production, make sure your deployment's CORS policy includes your Angular app's domain.

**Connection refused** -- If you see `ERR_CONNECTION_REFUSED`, verify your LangGraph server is running and that the `apiUrl` matches the correct host and port. Run `langgraph dev` and confirm the server starts at the expected address (default `http://localhost:2024`).

**Missing or incorrect API URL** -- The session needs an API URL, passed as `createSession({ apiUrl })`. Creating a session makes no request, so a missing URL or one that points at the wrong origin shows up when you submit the first run: `status()` becomes `'error'` and `error()` holds the failure.

**`createSession` is required** -- `provideAgent()` throws this `TypeError` when its config has no `createSession` function. The old `provideAgent({ apiUrl, assistantId })` form from `@threadplane/langgraph` no longer exists.

</Callout>
