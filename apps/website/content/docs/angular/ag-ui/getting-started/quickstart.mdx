# Quick Start

Connect the trip planner UI to a backend that emits AG-UI events. The session translates those events into the same Angular `Agent` that `<chat>` reads; the backend remains responsible for executing its agent and tools.

<Callout type="info" title="Prerequisites">
Angular 20–22 project using a Node.js version supported by that Angular major. If you need setup help, see the [Installation](/docs/angular/ag-ui/getting-started/installation) guide.
</Callout>

<Callout type="tip" title="Try it first">
Want to see the finished result before you build?

<CalloutActions>
  <CalloutAction href="https://ag-ui.threadplane.ai">Run AG-UI demo</CalloutAction>
</CalloutActions>
</Callout>

<Callout type="info" title="No backend yet?">
[Try without a backend](/docs/angular/chat/getting-started/try-without-a-backend) renders the same `<chat>` with a fake agent — no server, no key.
</Callout>

<Steps>
<Step title="Install the packages">

```bash
npm install @threadplane/angular @threadplane/core @threadplane/ag-ui @ag-ui/client marked
```

</Step>
<Step title="Configure the provider">

Add `provideAgent()` from `@threadplane/angular` to your application config, and give it a `createSession` factory that calls `createSession()` from `@threadplane/ag-ui` with your AG-UI backend URL.

```ts
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideAgent } from '@threadplane/angular';

export const appConfig: ApplicationConfig = {
  providers: [
    provideAgent({
      createSession: (context) =>
        import('@threadplane/ag-ui').then(({ createSession }) =>
          createSession({
            ...context,
            url: 'http://localhost:3000/agent',
          })
        ),
    }),
  ],
};
```

The agent calls the factory once when it is built and again each time it moves to another thread, and `context.threadId` is the thread the new session belongs to, or `null` for a new conversation. The factory returns a Promise, so `@threadplane/ag-ui` loads on demand, out of the initial bundle.

No backend yet? Swap to `provideFakeAgent()` from `@threadplane/angular/testing` - it serves canned streaming responses so you can build UI offline.

</Step>
<Step title="Use in a component">

```ts
import { Component } from '@angular/core';
import { ChatComponent } from '@threadplane/angular/chat';
import { injectAgent } from '@threadplane/angular';

@Component({
  selector: 'app-streaming',
  standalone: true,
  imports: [ChatComponent],
  template: `<chat [agent]="agent" />`,
})
export class StreamingComponent {
  protected readonly agent = injectAgent();
}
```

That is all. The `<chat>` composition handles streaming messages, tool calls, errors, and submit - all bound to the AG-UI backend through the injected `Agent`.

</Step>
</Steps>

## Follow one request

When the traveler sends a question, the session submits the conversation to the configured endpoint. Message events build the answer, tool events describe work, and state events update the observed application data. The terminal event tells the session that this run has finished; a message ending alone is not enough to establish that.

<TurnSequence />

AG-UI defines the event exchange. Durable threads, replay, and approval behavior depend on the backend integration. Read [Follow a conversation](/docs/angular/langgraph/concepts/conversation-turns) for the shared vocabulary, then [Event mapping](/docs/angular/ag-ui/reference/event-mapping) for the concrete protocol.

## Switching backends without changing UI

The framework-neutral session contract is the payoff: your component never learns which protocol it is talking to. The cost is one session implementation per backend, paid once, after which the UI code stops caring.

So swapping backends is a change to the session factory in `app.config.ts`, and the component code stays the same:

```diff
- import { createSession } from '@threadplane/langgraph';
- createSession({ ...context, apiUrl: '...', assistantId: '...' })   // LangGraph
+ import { createSession } from '@threadplane/ag-ui';
+ createSession({ ...context, url: '...' })  // AG-UI
```

There is one `provideAgent` and one `injectAgent`, both from `@threadplane/angular`. The two `createSession` functions are different functions from two different packages, each with its own options (`apiUrl` and `assistantId` for LangGraph, `url` for AG-UI). A component that reads a backend's own fields, such as the checkpoints of a LangGraph thread, depends on that backend.
