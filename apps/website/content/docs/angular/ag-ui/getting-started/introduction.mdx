# Introduction

> **Picking an adapter?** This guide covers `@threadplane/ag-ui` — the AG-UI protocol adapter. If you are talking to LangGraph Platform directly via the LangGraph SDK, use [`@threadplane/langgraph`](/langgraph) instead. See [Choosing an adapter](/docs/choosing-an-adapter) for a side-by-side comparison.

`@threadplane/ag-ui` runs an [AG-UI](https://github.com/ag-ui-protocol/ag-ui) backend behind the framework-neutral `AgentSession` contract from `@threadplane/core`. Its `createSession()` turns the AG-UI event protocol into a session, `provideAgent()` from `@threadplane/angular` hands that session to Angular as an injected `Agent` whose fields are Signals, and the chat UI primitives read that `Agent`.

<Callout type="info" title="What is AG-UI?">
AG-UI is an open agent-to-UI protocol. It standardizes how agent runtimes stream events (messages, tool calls, state updates) to a frontend. It is used by **CrewAI**, **Mastra**, **Microsoft Agent Framework**, **AG2**, **Pydantic AI**, and **AWS Strands**. One adapter unlocks all of them.
</Callout>

## What you get

- **`createSession({ url })`** - creates a session that posts each run to an AG-UI HTTP endpoint and reads the Server-Sent Events it answers with.
- **`createSession({ agent })`** - creates the same session over any AG-UI `AbstractAgent` you built (custom transports, mocks).
- **`provideAgent({ createSession })` and `injectAgent()`** - from `@threadplane/angular`. The one Angular provider builds an `Agent` from the session factory you pass it.
- **`FakeAgent`** - in-process `AbstractAgent` subclass that emits canned streaming events for offline demos and tests.

## What's covered

This is what the session handles today:
- `messages` (streaming token deltas via `TEXT_MESSAGE_*` events)
- `status` / `error` (lifecycle via `RUN_STARTED/FINISHED/ERROR`)
- `toolCalls` (streaming tool calls via `TOOL_CALL_*` events)
- `state` (snapshots and JSON-Patch deltas)
- `customEvents` and `onCustomEvent` (custom events)
- `interrupts` (from a `RUN_FINISHED` carrying an interrupt outcome, or from `CUSTOM` events named `on_interrupt` when `interruptTransport` selects a profile that answers them)
- `subagents` (from `SUBAGENT_*` events, or `ACTIVITY_*` with `activityType: 'subagent'`)

Out of scope for now (use `@threadplane/langgraph` if you need LangGraph Platform-specific APIs):
- Checkpoints and time-travel
