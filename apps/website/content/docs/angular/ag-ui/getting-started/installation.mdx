# Installation

Supported Angular majors: 20, 21, and 22.

Use a Node.js version supported by the selected Angular major. Angular 22 supports Node.js ^22.22.3, ^24.15.0, or ^26.0.0. See the [Angular compatibility matrix](https://angular.dev/reference/versions).

## Prerequisites

- Angular 20, 21, or 22
- An AG-UI-compatible backend running locally or remotely (CrewAI, Mastra, Microsoft Agent Framework, AG2, Pydantic AI, AWS Strands, or your own subclass of `AbstractAgent`)

## Install packages

```bash
npm install @threadplane/chat @threadplane/angular @threadplane/core @threadplane/ag-ui @ag-ui/client marked
```

`@threadplane/chat` provides the chat UI primitives. `@threadplane/ag-ui` provides `createSession()`, which runs an AG-UI backend behind the framework-neutral session contract from `@threadplane/core`. `@threadplane/angular` provides `provideAgent()` and `injectAgent()`, which turn that session into the `Agent` the primitives consume.
`marked` is the required markdown parser peer used by `@threadplane/chat` when assistant messages render through `<chat>`.

## Peer Dependencies

`@threadplane/ag-ui` contains no UI framework code and declares the following peer dependencies:

| Package             | Version   |
| ------------------- | --------- |
| `@threadplane/core` | `0.3.7`   |
| `@ag-ui/client`     | `^1.0.1`  |
| `rxjs`              | `~7.8.0`  |

`@threadplane/angular` declares `@angular/core` at `^20.0.0 || ^21.0.0 || ^22.0.0` and `@threadplane/core` and `@threadplane/content` at `0.3.7`. RxJS is the stream type of the AG-UI client itself; `@threadplane/ag-ui` uses it only for `FakeAgent`.

## Configure the provider

In your app config:

```ts
import { ApplicationConfig } from '@angular/core';
import { provideAgent } from '@threadplane/angular';
import { createSession } from '@threadplane/ag-ui';

export const appConfig: ApplicationConfig = {
  providers: [
    provideAgent({
      createSession: (context) =>
        createSession({
          url: 'http://localhost:3000/agent', // your AG-UI backend
          threadId: context.threadId ?? undefined,
        }),
    }),
  ],
};
```

`provideAgent` takes the session factory. The agent calls it once when it is built and again each time it moves to another thread, always in an injection context, so the factory may call `inject()`. `context.threadId` is the thread the new session belongs to, or `null` when there is none yet.

`createSession` accepts:

| Option               | Type                              | Description                                                                                                                  |
| -------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `url`                | `string`                          | AG-UI backend HTTP/SSE endpoint. Required unless `agent` is given.                                                           |
| `agent`              | `AbstractAgent`                   | An AG-UI client agent you built, in place of `url`. Passing both throws.                                                     |
| `agentId`            | `string`                          | Optional. Names the agent when an endpoint serves more than one.                                                             |
| `threadId`           | `string`                          | Optional. The thread this session owns. Absent, the session generates one. An empty string throws.                           |
| `headers`            | `Record<string, string>`          | Optional. Custom request headers (auth, tracing). Belongs to the `url` form.                                                 |
| `interruptTransport` | `InterruptTransport`              | Optional. How a pause is answered. Defaults to `'protocol'`. See [Interrupts](/docs/angular/ag-ui/guides/interrupts).        |
| `replay`             | `ReplaySource`                    | Optional. Loads the thread's events from your server when the session is created.                                            |
| `persistence`        | `SessionPersistence`              | Optional. Application-owned storage for the thread. Needs a `threadId` the application chose.                                |
| `telemetry`          | `SessionTelemetrySink \| false`   | Optional. App-owned sink for session lifecycle events.                                                                       |

## Use in a component

```ts
import { Component } from '@angular/core';
import { ChatComponent } from '@threadplane/chat';
import { injectAgent } from '@threadplane/angular';

@Component({
  selector: 'app-streaming',
  standalone: true,
  imports: [ChatComponent],
  template: `<chat [agent]="agent" />`,
})
export class StreamingComponent {
  protected readonly agent = injectAgent();
}
```

## No backend yet?

Use `provideFakeAgent()` for offline demos:

```ts
import { ApplicationConfig } from '@angular/core';
import { provideFakeAgent } from '@threadplane/angular/testing';

export const appConfig: ApplicationConfig = {
  providers: [
    provideFakeAgent({
      tokens: ['Hello', ' from', ' a', ' fake', ' agent.'],
      reasoningTokens: ['Thinking', ' it', ' over...'],
      delayMs: 60,
    }),
  ],
};
```

`provideFakeAgent()` provides the same `Agent` that `provideAgent()` builds, over an in-memory session that streams a canned reply to each submit. No AG-UI event is involved. It is a drop-in replacement for `provideAgent()` while you are prototyping.

`provideFakeAgent` accepts:

| Option            | Type       | Description                                                                         |
| ----------------- | ---------- | ----------------------------------------------------------------------------------- |
| `tokens`          | `string[]` | Optional. Tokens streamed back as the assistant reply.                              |
| `reasoningTokens` | `string[]` | Optional. Reasoning text streamed before the reply.                                 |
| `delayMs`         | `number`   | Optional. Milliseconds between entries (defaults to `60`; `0` streams without timers). |

To run the real AG-UI session without a backend, hand it the `FakeAgent` from `@threadplane/ag-ui` instead. See [Fake Agent](/docs/angular/ag-ui/guides/fake-agent).

## Custom transport

If you have a backend that speaks AG-UI but not over HTTP, subclass `AbstractAgent` directly and pass it to `createSession` as `agent`:

```ts
import {
  AbstractAgent,
  type RunAgentInput,
  type BaseEvent,
} from '@ag-ui/client';
import { Observable } from 'rxjs';
import { provideAgent } from '@threadplane/angular';
import { createSession } from '@threadplane/ag-ui';

class MyCustomAgent extends AbstractAgent {
  run(input: RunAgentInput): Observable<BaseEvent> {
    // Your custom transport (WebSocket, in-process worker, etc.)
    // emits BaseEvent events.
    return new Observable<BaseEvent>((observer) => {
      observer.complete();
    });
  }
}

provideAgent({
  createSession: (context) =>
    createSession({
      agent: new MyCustomAgent(),
      threadId: context.threadId ?? undefined,
    }),
});
```

The session calls the agent's `run(input)` with each request's full input. It does not call `runAgent`, and it neither reads nor changes the agent's own `messages` and `state`.
