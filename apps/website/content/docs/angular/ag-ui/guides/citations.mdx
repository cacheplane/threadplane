# Citations

`@threadplane/ag-ui` reads citations from AG-UI state onto chat messages.

AG-UI has no citation event, so a backend sends sources as application state. The convention is deliberately simple: put citations under `state.citations`, keyed by message id. Each assistant message the session publishes carries the sources listed for its id.

## State shape

Use this shape from your AG-UI backend:

```ts
{
  citations: {
    "assistant-message-id": [
      {
        id: "doc-1",
        title: "Refund policy",
        url: "https://example.com/refunds",
        snippet: "Refunds are available within 30 days."
      }
    ]
  }
}
```

The key must be the assistant message's current id: the one emitted by `TEXT_MESSAGE_START`, or the saved id when the backend's `MESSAGES_SNAPSHOT` renames the message.

```ts
{ type: 'TEXT_MESSAGE_START', messageId: 'm1', role: 'assistant' }
{ type: 'TEXT_MESSAGE_CONTENT', messageId: 'm1', delta: 'Refunds are available.' }
{
  type: 'STATE_SNAPSHOT',
  snapshot: {
    citations: {
      m1: [
        {
          id: 'refund-policy',
          title: 'Refund policy',
          url: 'https://example.com/refunds',
          snippet: 'Refunds are available within 30 days.',
        },
      ],
    },
  },
}
```

The message becomes:

```ts
{
  id: 'm1',
  role: 'assistant',
  content: 'Refunds are available.',
  citations: [
    {
      id: 'refund-policy',
      index: 1,
      title: 'Refund policy',
      url: 'https://example.com/refunds',
      snippet: 'Refunds are available within 30 days.',
    },
  ],
}
```

## Accepted citation fields

The session normalizes a few common field names:

| Citation field | Accepted input |
| --- | --- |
| `id` | `id`, `refId`, or generated `c1`, `c2`, ... |
| `index` | `index` or array position starting at 1 |
| `title` | `title` or `name` |
| `url` | `url`, `href`, or `source` |
| `snippet` | `snippet`, `content`, or `excerpt` |
| `sourceType` | `sourceType` string |
| `iconUrl` | `iconUrl` string |
| `publishedAt` | `publishedAt` as a string or a finite number |
| `extra` | `extra` object |

String entries are also accepted:

```ts
{
  citations: {
    m1: ['https://example.com/refunds']
  }
}
```

That becomes:

```ts
{ id: 'c1', index: 1, url: 'https://example.com/refunds' }
```

## When citations update

Citations reach the state through:

- `STATE_SNAPSHOT`
- `STATE_DELTA`

Plain text events carry none. If your backend streams the final answer first and citations later, send a state event after citation data is available.

The session reads `state.citations` each time it publishes its messages, so the order of the two does not matter: sources that arrive before their message exists appear once the message does. A backend that saves a message under a new id lists its sources under the saved id, so they appear once the `MESSAGES_SNAPSHOT` arrives.

## Manual bridge

`bridgeCitationsState()` is exported for messages held outside a session.

```ts
import { bridgeCitationsState } from '@threadplane/ag-ui';

const nextMessages = bridgeCitationsState(
  { state: threadState },
  currentMessages,
);
```

Most apps should not need this directly. A session already does this for the messages it publishes. The `bridgeCitationsState(thread, messages)` helper attaches thread-level citation state to a message list; import it from `@threadplane/ag-ui` when you assemble messages yourself outside a session.

## Gotchas

Citation matching is by message id, not by order. Stable message ids matter.

The helper returns messages unchanged when `state.citations` is missing, is not an object, or the entry for a message is absent, not an array, or empty.

The session normalizes citation shape; it does not fetch metadata, validate URLs, or deduplicate sources across messages.
