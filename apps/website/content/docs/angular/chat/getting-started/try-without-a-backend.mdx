# Try without a backend

Render a real `<chat>` in your Angular app with no server, no LLM and no account. `provideFakeAgent()` streams a canned reply in-process through the same components you will ship. When the UI looks right, swap the provider for `provideAgent()` and a real session.

<Callout type="info" title="What you need">
An Angular 20–22 application. Nothing else.
</Callout>

<Steps>
<Step title="Install">

```bash
npm install @threadplane/angular @threadplane/core @threadplane/langgraph @langchain/core @langchain/langgraph-sdk marked
```

`provideFakeAgent()` ships in the `@threadplane/angular/testing` entry and runs on the in-memory session from `@threadplane/core/testing`. Both packages are also peers of `@threadplane/angular/chat`; the command names them because your application imports from them directly. The fake needs no backend package: `@threadplane/langgraph` and its LangChain peers are here so the last step can swap in a real session, and you can install the backend you expect to use instead. `marked` renders assistant markdown.

<Callout type="tip" title="Bundle budget">
A default Angular application caps the initial bundle at 1 MB. If `ng build` reports a budget error after you add the chat UI and a backend package, raise `budgets[].maximumError` for the `initial` bundle in `angular.json`.
</Callout>

</Step>
<Step title="Provide the fake agent">

```ts
// app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideFakeAgent } from '@threadplane/angular/testing';

export const appConfig: ApplicationConfig = {
  providers: [
    provideFakeAgent({ tokens: ['Hello', ' from', ' Threadplane.'] }),
  ],
};
```

`FakeAgentConfig` accepts `tokens`, `reasoningTokens` and `delayMs` (60 milliseconds between entries by default; `0` streams without timers), plus `threadId`, `onThreadId` and a `session` object that seeds the fake session's snapshot. Leave them out and the fake agent streams a default reply. `@threadplane/angular/chat/testing` re-exports `provideFakeAgent()` if you would rather import it from the chat package.

</Step>
<Step title="Render the chat">

```ts
// app.component.ts
import { Component } from '@angular/core';
import { injectAgent } from '@threadplane/angular';
import { ChatComponent } from '@threadplane/angular/chat';

@Component({
  selector: 'app-root',
  imports: [ChatComponent],
  template: `<chat [agent]="agent" />`,
})
export class AppComponent {
  protected readonly agent = injectAgent();
}
```

Run `ng serve`, type anything, and watch the reply stream in.

</Step>
<Step title="Test it">

```ts
// app.component.spec.ts
import { TestBed } from '@angular/core/testing';
import { provideFakeAgent } from '@threadplane/angular/testing';
import { AppComponent } from './app.component';

it('streams the fake reply', async () => {
  TestBed.configureTestingModule({
    imports: [AppComponent],
    providers: [provideFakeAgent({ tokens: ['Hello', ' from', ' Threadplane.'], delayMs: 0 })],
  });
  const fixture = TestBed.createComponent(AppComponent);
  fixture.detectChanges();
  const textarea = fixture.nativeElement.querySelector('textarea');
  textarea.value = 'hi';
  textarea.dispatchEvent(new Event('input'));
  fixture.detectChanges();
  fixture.nativeElement.querySelector('button[aria-label="Send message"]').click();
  await fixture.whenStable();
  fixture.detectChanges();
  expect(fixture.nativeElement.textContent).toContain('Hello from Threadplane.');
});
```

The `detectChanges()` call after the input event matters: the send button stays disabled until change detection runs, so a click before it does nothing.

</Step>
</Steps>

## Testing without a model

`provideFakeAgent()` streams canned tokens in-process, so component specs stay deterministic and fast. Three more helpers cover the rest:

- `injectFakeAgentSession()` from `@threadplane/angular/testing` returns a signal of the current fake session's controls, so a spec can push messages, set an error, or publish interrupts and tool calls.
- `mockAgent()` from `@threadplane/angular/chat` builds an `Agent` with writable fields and recorded commands for a component test that needs no injector: `agent.messages.set([...])`, `agent.status.set('running')`, then assert on `agent.submitCalls`.
- `MockAgentTransport` from `@threadplane/langgraph` and `FakeAgent` from `@threadplane/ag-ui` script backend events through the real session when a spec has to cover the projection too.

See the [testing guide](/docs/angular/langgraph/guides/testing).

## Connect a real backend

Replace `provideFakeAgent(...)` with `provideAgent({ createSession })` from `@threadplane/angular`, and keep every component as it is:

- **LangGraph**: `createSession` from `@threadplane/langgraph` — [LangGraph quickstart](/docs/angular/langgraph/getting-started/quickstart)

  ```ts
  provideAgent({
    createSession: (context) =>
      createSession({
        ...context,
        apiUrl: 'http://localhost:2024',
        assistantId: 'agent',
      }),
  })
  ```

- **AG-UI**: install `@threadplane/ag-ui @ag-ui/client rxjs`, then use `createSession` from `@threadplane/ag-ui` — [AG-UI quickstart](/docs/angular/ag-ui/getting-started/quickstart)

  ```ts
  provideAgent({
    createSession: (context) =>
      createSession({
        ...context,
        url: 'http://localhost:8000/agent',
      }),
  })
  ```

Not every backend emits every capability; see [Choosing an adapter](/docs/choosing-an-adapter).
