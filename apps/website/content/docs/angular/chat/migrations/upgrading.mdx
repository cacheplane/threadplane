# Upgrade an integration

Upgrade the parts that exchange data together: the frontend packages, their protocol peers, the backend producer, and any persisted schema they share. Start by identifying the API your application actually uses, then follow the relevant migration below. This page does not announce a package release. The move to the session provider and the client-tool ownership protocol below describe source changes that are not in a published release yet.

## Identify the integration first

| Application | Contract to check |
|---|---|
| Angular chat | `@threadplane/chat` components, `@threadplane/angular`, `@threadplane/core`, and the chosen backend package with its declared peers. |
| LangGraph backend | Graph state, checkpoint storage, and the SDK protocol consumed by the session. |
| AG-UI backend | Event shapes, protocol peers, and that runtime's interrupt/replay conventions. |
| React source build | The private `@threadplane/react` binding over the same `@threadplane/core` sessions. |

The Angular `Agent` is a signal view of an `AgentSession`: the same session contract serves both frameworks, and the bindings differ in ownership. `injectAgent()` returns an agent that creates and disposes its sessions; the React `useAgent` hook observes a session its application owns. Replacing one with the other is not a migration. Follow the [conversation guide](/docs/angular/langgraph/concepts/conversation-turns) when evaluating either path.

## Move to the session provider

The Angular agent now runs on the framework-neutral `AgentSession` contract from `@threadplane/core`. `@threadplane/langgraph` and `@threadplane/ag-ui` no longer contain Angular code: each exports a `createSession()` factory, and one provider in `@threadplane/angular` turns any session into the injected `Agent`. There is no compatibility layer, so an application moves in one step. `<chat>` and the other components keep their selectors; what changes is where the agent comes from and the names of its members.

Work through the checklist in order. Each step compiles on its own once the imports in step 2 are in place.

### 1. Install the new packages

Your application now imports from `@threadplane/angular` and `@threadplane/core` directly, so add both. `@threadplane/ag-ui` no longer has `@ag-ui/core` as a peer.

```bash
# LangGraph
npm install @threadplane/angular @threadplane/core

# AG-UI
npm install @threadplane/angular @threadplane/core
npm uninstall @ag-ui/core   # only if your own code does not import it
```

Keep every `@threadplane/*` package on the same version.

### 2. Replace the provider

`provideAgent` and `injectAgent` come from `@threadplane/angular`. The backend options move into a `createSession` factory, which the agent calls once when it is built and again for each thread it opens.

Before, LangGraph:

```ts
import { provideAgent } from '@threadplane/langgraph';

provideAgent({
  apiUrl: 'http://localhost:2024',
  assistantId: 'chat',
  threadId: activeThreadId,
  onThreadId: (id) => activeThreadId.set(id),
});
```

After:

```ts
import { provideAgent } from '@threadplane/angular';
import { createSession } from '@threadplane/langgraph';

provideAgent({
  // Agent options: the thread to follow, and the callback for a created thread.
  threadId: activeThreadId,
  onThreadId: (id) => activeThreadId.set(id),
  // Session options: everything about the backend.
  createSession: (context) =>
    createSession({
      ...context,
      apiUrl: 'http://localhost:2024',
      assistantId: 'chat',
    }),
});
```

Before, AG-UI:

```ts
import { provideAgent } from '@threadplane/ag-ui';

provideAgent({ url: 'http://localhost:8000/agent' });
```

After:

```ts
import { provideAgent } from '@threadplane/angular';
import { createSession } from '@threadplane/ag-ui';

provideAgent({
  createSession: (context) =>
    createSession({
      ...context,
      url: 'http://localhost:8000/agent',
    }),
});
```

- [ ] Change every `injectAgent` import to `@threadplane/angular`.
- [ ] Spread the provider context into the session options: `createSession({ ...context, ... })`. It carries the thread to open, the callback that reports a thread the session created, the app-wide client options, the operation-failure reporter and the development telemetry relay, each under the option name both backends accept. A factory that names fields instead drops the ones it leaves out; without the thread, a thread switch opens the wrong conversation.
- [ ] A config that needs injected values becomes a factory: `provideAgent(() => ({ createSession: ... }))`. It runs once, in an injection context, and `createSession` itself may call `inject()` too.
- [ ] Replace `toAgent(source)` with `createSession({ agent: source })` inside the factory.
- [ ] Replace `LANGGRAPH_CLIENT_OPTIONS` with `provideAgentClientOptions(options)` from `@threadplane/angular`, and read it in the factory as `context.clientOptions`.
- [ ] Replace the `LangGraphAgent` and `AgUiAgent` types with `Agent<LangGraphSession>` and `Agent<Session>` (`Agent` from `@threadplane/angular`, the session types from the backend packages). For typed injection, use `createAgentRef<LangGraphSession>('name')`, `provideAgent(ref, config)` and `injectAgent(ref)`, or name the type at the call site: `injectAgent<LangGraphSession>()`.

### 3. Rename the agent members

The injected `Agent` is exactly the session's snapshot fields as signals plus the session's commands. The legacy names are gone.

| Before | After |
|---|---|
| `agent.isLoading()` | `agent.status() === 'running'` |
| `agent.interrupt()` | `agent.interrupts()?.[0]` |
| `agent.submit({ message: 'Hi' })` | `agent.submit('Hi')`, or `agent.submit({ message: 'Hi', state })` to merge state first |
| `agent.submit({ resume: value })` | `agent.resume([{ interruptId, status: 'resolved', value }])` |
| `agent.regenerate(index)` | `agent.regenerate(agent.messages()[index].id)` |
| `agent.reload()` | `agent.retry()` |
| `agent.history()` | `agent.checkpoints()` |
| `agent.subagents()` as a `Map` | `agent.subagents()` as a list, or `undefined` when the session reports none |
| `agent.events$` | `agent.onCustomEvent(listener)`, or the retained `agent.customEvents()` |
| `agent.isInputBlocked()` | `agent.inputBlocked()`, an object with a `reason` while input is refused |
| `agent.clientTools.pending()` | `agent.pendingClientTools()` |

```ts
// Before
if (agent.isLoading()) return;
const pending = agent.interrupt();
if (pending) await agent.submit({ resume: { approved: true } });

// After
if (agent.status() === 'running') return;
const pending = agent.interrupts()?.[0];
if (pending && agent.resume) {
  await agent.resume([
    { interruptId: pending.id, status: 'resolved', value: { approved: true } },
  ]);
}
```

- [ ] `submit`, `resume`, `retry` and `regenerate` now resolve with the run's outcome (`'success'`, `'error'`, `'aborted'`, `'interrupted'` or `'paused'`) instead of `void`.
- [ ] `resume`, `retry`, `regenerate`, `runWithoutMessage`, `checkStatus` and `onCustomEvent` are optional. A command the session does not offer is `undefined`; check before you call it, and offer no control for it.
- [ ] `interrupts()`, `subagents()`, `plan()`, `checkpoints()`, `inputBlocked()` and `pendingClientTools()` are `undefined` on a session that reports none.
- [ ] `threadId()`, `isThreadLoading()`, `switchThread(id)`, `customEvents()` and `lifecycle` keep their names.
- [ ] LangGraph per-run settings (`command`, `multitaskStrategy`, `interruptBefore`, `streamMode`, `checkpointId` and the rest) move under `options.run`: `agent.submit(text, { run: { multitaskStrategy: 'enqueue' } })`. A setting at the root of the options is not read.

### 4. Replace the thread adapter

`LangGraphThreadsAdapter`, `LANGGRAPH_THREADS_CONFIG` and `LANGGRAPH_CLIENT` are removed. Provide a thread directory instead.

Before:

```ts
import { LANGGRAPH_THREADS_CONFIG, LangGraphThreadsAdapter } from '@threadplane/langgraph';

providers: [
  { provide: LANGGRAPH_THREADS_CONFIG, useValue: { apiUrl: 'http://localhost:2024' } },
];

readonly threads = inject(LangGraphThreadsAdapter);
```

After:

```ts
import { injectThreadDirectory, provideThreadDirectory } from '@threadplane/angular';
import { createLangGraphThreadDirectory } from '@threadplane/langgraph';

providers: [
  provideThreadDirectory({
    createDirectory: (context) =>
      createLangGraphThreadDirectory({ ...context, apiUrl: 'http://localhost:2024' }),
  }),
];

readonly threads = injectThreadDirectory();
```

- [ ] The view keeps `threads()`, `archivedThreads()`, `projects()`, `status()`, `error()`, `refresh()`, `create()`, `getThread()` and the row commands, and adds `isLoading()`. `threads.directory` is still what `<chat-thread-sidebar [directory]>` takes.
- [ ] Nothing is loaded until `refresh()` is called. `<chat-thread-sidebar>` calls it when it mounts.
- [ ] `refreshOnRunEnd` and `refreshOnTransition` move to `@threadplane/angular`.
- [ ] `getThread(id)` reads one thread from the backend, so it answers for any thread, listed or not, and resolves `null` for one that does not exist. Name the directory type, `injectThreadDirectory<LangGraphThreadDirectory>()`, to call the row commands without `?.`.
- [ ] Projects are configured on the directory: `createLangGraphThreadDirectory({ projects: false })` turns them off.

### 5. Update the testing imports

| Before | After |
|---|---|
| `provideFakeAgent` from `@threadplane/langgraph` or `@threadplane/ag-ui` | `provideFakeAgent` from `@threadplane/angular/testing`, also re-exported by `@threadplane/chat/testing` |
| `mockLangGraphAgent()` | `mockAgent()` from `@threadplane/chat` |
| `runAgentConformance(label, () => agent)` | `runAgentConformance(label, () => session)`: the factory returns an `AgentSession` |
| A hand-written fake `Agent` | `createFakeAgentSession()` from `@threadplane/core/testing`, or `mockAgent()` |

- [ ] `mockAgent()` fields are written with `set`: `agent.status.set('running')` replaces a separate `isLoading` signal, and `agent.interrupts.set([{ id: 'i1', value }])` replaces `interrupt.set(...)`.
- [ ] To script backend events through the real projection, pass `MockAgentTransport` as `createSession({ transport })` for LangGraph, or `new FakeAgent()` as `createSession({ agent })` for AG-UI.
- [ ] `injectFakeAgentSession()` from `@threadplane/angular/testing` gives a spec the controls of the fake session behind `provideFakeAgent()`.

### 6. Opt back in to what used to be default

A LangGraph session makes no request and keeps no large data until asked. Add the option to `createSession()` for each behaviour your application relied on.

| Option | What it restores |
|---|---|
| `throttle: 16` | Paces change notifications while a run streams. The legacy agent used 16 milliseconds; a session notifies on every change unless told otherwise. |
| `historyState: true` | Keeps each checkpoint's state, so `checkpoints()`, `messageCheckpoints()` and `branchTree()` are published. Needed by the timeline, the timeline slider and the debug panel. |
| `restoreSubagents: true` | Rebuilds child agents from the saved thread when history is loaded, so subagent cards come back after a reload. |
| `rawMessages: true` | Publishes `langGraphMessages()`, `messageMetadata()` and `Message.extra`. |
| `transcriptNodeNames` | Limits which root nodes' streamed messages enter the transcript. |
| `subagentToolNames` | Names the tools that start a child agent; `['task']` when omitted. |
| `autoLoad: true` | Reads history as soon as a session is created and publishes `loading()`. The Angular agent already calls `load()` for each thread it opens and reports it as `isThreadLoading()`, so most applications do not need this. |

- [ ] `clientOptions.maxRetries` defaults to `0` on the session's own transport, and a non-zero value is an explicit choice to let the SDK retry requests.

### 7. Set the AG-UI interrupt transport

`interruptTransport` now defaults to `'protocol'`: a session answers only the protocol's own interrupt outcome. The legacy default was `'auto'`, which also answered a `CUSTOM on_interrupt` notice through `forwardedProps.command`.

- [ ] If your backend pauses with a `CUSTOM on_interrupt` event, pass `interruptTransport: 'auto'` (or `'legacy-command'` or `'mastra-command'`) to `createSession()`. Without it the notice is shown and cannot be answered.

```ts
provideAgent({
  createSession: (context) =>
    createSession({
      ...context,
      url: 'http://localhost:8000/agent',
      interruptTransport: 'auto',
    }),
});
```

### 8. Check the result

- [ ] Search the application for `@threadplane/langgraph` and `@threadplane/ag-ui` imports. Only `createSession`, session types, thread-directory factories, transports and testing fakes should remain.
- [ ] Search for `isLoading()`, `interrupt()`, `history()`, `events$`, `submit({` and `regenerate(` on an agent.
- [ ] Run the journey under [Verify the user journey after upgrading](#verify-the-user-journey-after-upgrading), including a thread switch and a reload of a saved thread.

## Keep package peers aligned

Read the installed package manifests and the [changelog](/docs/angular/chat/getting-started/changelog) before updating. The current Angular packages declare support for Angular 20, 21, and 22; select a supported major and compatible Node version for your application.

The AG-UI package's move from the 0.0.x protocol packages to the 1.x line requires a compatible `@ag-ui/client` peer. The current package manifest requires `^1.0.1`. Review [installation](/docs/angular/ag-ui/getting-started/installation) and [event mapping](/docs/angular/ag-ui/reference/event-mapping), then exercise an actual message, tool result, and approval if your backend supports them.

## Regenerate older A2UI surfaces

The A2UI v0.9.1 migration changed the earlier draft wire format. Update the backend that authors surfaces and the frontend that parses them together. The current wire constant is still `A2UI_WIRE_VERSION = 'v0.9'`; do not invent a `v0.9.1` envelope version from the migration label.

The current format uses `createSurface`, `updateComponents`, `updateDataModel`, and `deleteSurface` envelopes. Components are flat entries with an ID, a component name, and properties. Compare generated fixtures and prompts with the [message protocol](/docs/angular/a2ui/guides/message-protocol) and [schema reference](/docs/angular/a2ui/reference/schema). Recreate old draft surfaces using that contract rather than relabeling their version field.

Validate the round trip your application uses: render a surface, edit a bound field, submit an action, and process the resulting data-model update. A parser accepting a line is not equivalent to the whole application supporting every catalog component or action.

## Migrate persisted client-tool execution data deliberately

The invocation-ownership protocol in the source tree is **unreleased** and separate from the legacy Angular chat execution guard. Its factory names remain, but its store uses `acquire` and `settle` rather than the removed `claim`, `record`, and `lookup` port. Renaming methods alone does not migrate the contract.

For an existing PostgreSQL integration adopting this source-tree protocol:

1. Drain active executions and all writers, including custom SQL paths.
2. Audit those custom writers before applying the explicit `THREADPLANE_CLIENT_TOOL_EXECUTIONS_MIGRATION`.
3. Deploy the matching runtime and provider integration with the migrated schema.
4. Resume work only after those parts agree on invocation identity and ownership tokens.

Construction performs no DDL. The migration preserves existing identity and historical data, but it does not certify historical results or reopen unknown executions. Missing ownership tokens become legacy-unknown. The required token column blocks the former factory's writes, while custom direct updates need their own audit.

The source tree also removes the receipt helpers `extractClientToolResultMessages`, `filterDuplicateClientToolResultMessages`, `lookupClientToolExecutions`, and `recordClientToolResults`, together with their helper-only types. Remove their receipt-ingestion/filtering code; there is no replacement receipt helper or compatibility alias. A stored tool result is not proof that a graph consumed it and does not guarantee exactly-once effects in an external service.

Use the [middleware migration details](/docs/shared/middleware/getting-started/introduction#breaking-invocation-ownership-protocol-unreleased) as the complete contract, including non-reusable results, conflicts, and external reconciliation.

## Verify the user journey after upgrading

Start with one conversation: submit a question, observe incremental text, stop active work, and inspect the resulting state. Then exercise the capabilities your application uses: tool results, approvals, generated UI, and reopening a saved thread. Check a restored conversation as well as a new one; migrations can affect old persisted data without affecting a fresh demo.

The [testing guide](/docs/angular/langgraph/guides/testing), [AG-UI tests](/docs/angular/ag-ui/guides/testing), and the canonical examples provide narrower checks for each boundary. Keep release/version decisions separate from adopting the source changes described here.
