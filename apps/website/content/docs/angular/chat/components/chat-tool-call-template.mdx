# ChatToolCallTemplateDirective

`ChatToolCallTemplateDirective` registers a per-tool-name template inside `<chat-tool-calls>`. The primitive collects all directive instances and dispatches each tool call to the template matching its `name`. A literal `"*"` registers a wildcard catch-all for any unmapped name.

**Selector:** `[chatToolCallTemplate]`

**Import:**

```typescript
import { ChatToolCallTemplateDirective, type ChatToolCallTemplateContext } from '@threadplane/angular/chat';
```

## Template context

Each registered template receives:

| Variable | Type | Description |
|---|---|---|
| `let-call` (`$implicit`) | `ToolCall` | The full tool call: `id`, `name`, `args` and `status`, with `result` on a `complete` call and `error` (a string) on an `error` call |
| `let-status="status"` | `ToolCallStatus` | `'pending' \| 'running' \| 'complete' \| 'error'` |

`args` and `result` are plain data whose shape belongs to the tool, and `result` exists only on a `complete` call. The examples below read the result through `resultOf`, a component field set to `toolCallResult` from `@threadplane/angular/chat`, which returns `undefined` for a call that has none. Narrow `args` in the component class the same way when your templates are type-checked strictly.

## Examples

### Custom search-result card

```html
<chat-tool-calls [agent]="agent" [message]="msg">
  <ng-template chatToolCallTemplate="search_web" let-call let-status="status">
    <my-search-result-card
      [query]="call.args.query"
      [results]="resultOf(call)"
      [status]="status"
    />
  </ng-template>
</chat-tool-calls>
```

### Wildcard catch-all

```html
<chat-tool-calls [agent]="agent" [message]="msg">
  <ng-template chatToolCallTemplate="search_web" let-call let-status="status">
    <my-search-result-card [query]="call.args.query" [results]="resultOf(call)" />
  </ng-template>

  <!-- Anything not search_web falls through to here -->
  <ng-template chatToolCallTemplate="*" let-call>
    <chat-tool-call-card [toolCall]="call" />
  </ng-template>
</chat-tool-calls>
```

### Project through `<chat>` directly

`<chat>` collects every `chatToolCallTemplate` placed as a direct child and passes them to the inner `<chat-tool-calls>` of each assistant message:

```html
<chat [agent]="agent">
  <ng-template chatToolCallTemplate="generate_image" let-call let-status="status">
    <my-image-card
      [prompt]="call.args.prompt"
      [imageUrl]="resultOf(call)"
      [status]="status"
    />
  </ng-template>
</chat>
```

When a [`chatActivityTemplate`](/docs/angular/chat/components/chat-activity-template) is also projected into `<chat>`, it owns the whole tool-call region and these templates are not used.

## Dispatch order

1. Per-tool template whose `name` exactly matches `tc.name`.
2. Wildcard template with `name === "*"`.
3. Default `<chat-tool-call-card>` (no template registered for either).
