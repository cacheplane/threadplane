# Memory

Deep Agents maintains `/memories/AGENTS.md` itself through `write_file` and `edit_file`. The shared Python graph uses `StoreBackend`, so a fresh conversation can recall the file from the store rather than from an earlier transcript. Angular remains the default on this guide. The experimental React preview uses native React chat components and the same graph and prompt.

## Teach and recall

In Angular Run, **Tell it about your operation** sends the suggested prompt immediately. Reload before asking what the agent remembers to start a new thread under the same browser identity. The Angular panel renders trimmed nonblank lines. In React, **Teach** and **Recall** only fill a draft; explicit **Send** or Enter authors a turn. React preserves literal blank lines, Unicode and whitespace, displays full tool arguments and results, and renders assistant Markdown.

Opening either example does not create a thread. React also keeps mode changes, history navigation, unsent drafts, New and saved-history selection free of authoring. New clears the React draft and local view; reload clears the retained local catalog. A successful followup reuses the owned thread; New or reload creates a fresh thread lazily on the next Send.

## Capture the browser scope

The storage key `threadplane.deep-agents-memory.scope.v1` stores a canonical UUIDv4. Each app generation captures the persisted readback winner and supplies exactly `context: { memory_scope }`. The namespace is `('cockpit', 'deep-agents-memory', 'browser-v1', scope)`. New conversations retain the same scope while storage is available.

Storage is partitioned by origin and browser storage partition. Angular and React on the same origin share the key; local development ports have different origins. Unavailable or corrupt storage blocks authoring before SDK thread creation. Replacement or deletion later blocks future turns. An already active turn may settle under its captured scope with a warning. There is no read, migration or reset of the historical global namespace.

<Callout type="warning" title="Logical partition, not authentication">
A browser UUID is not authorization. Public state APIs fall outside this scope guarantee. Derive an authenticated namespace and enforce server authorization when your application requires it.
</Callout>

## Fresh observations

The graph reads the actual store initially, before every model call and at terminal completion. A missing file is `{}`; a present empty file is `''`. Reads validate strict UTF-8 and at most 65,536 bytes after downloading and materializing the file. The bound does not limit store allocation. The pinned middleware strips HTML comments and trailing whitespace from the model prompt; custom events, raw checkpoints and the React panel retain literal contents.

The named `deep_agents.memory` custom event contains `memory_contents`, `memory_scope_owner` and `phase`. Angular's **store observed during this run** comes from this live event. Historical state/checkpoint reads are a distinct fallback. A live observation is read-time evidence, not durability, and checkpoints do not promise that the store remains current.

The graph's private input/output schema annotations omit Memory keys from API `values` filtered through `graph.output_channels`. Custom events, checkpoint events and raw checkpoints retain those keys. This is not a secrecy guarantee; unfiltered local graph streams can include private values.

## React confirmation and restoration

React labels custom evidence **store observed during this run**. **confirmed checkpoint at read time** and **Response saved.** require native success plus matching current root state, a fresh newest history head, an exact checkpoint and actual native transcript/load. Only absent private Memory keys may be omitted from live values; ordinary values and the complete tool transcript must match. Loaded values must match fully.

Saved conversations restore an exact retained historical checkpoint through reads only. A failed initial, model or terminal read, partial failed observation, oversized file or failed checkpoint read cannot confirm Saved. A terminal read failure after a successful write can leave the write persisted: confirmation is cleared and there is no rollback. Stop cancels local delivery while backend work may continue. New invalidates stale results. Conversations can update the same file at the same time; concurrent conversations are not serialized.

React uses `ifExists: 'raise'` and `maxRetries: 0`, with no automatic Retry, replay or Resume. Its package remains a private source-build preview.

## Source and verification

Browser fixtures and verification controls are excluded from public Code and production builds.
