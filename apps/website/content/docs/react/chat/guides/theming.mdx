# React chat theming preview

Give the same conversation a different visual theme without replacing its session. Colors, typography, and surfaces belong to presentation state, so changing a palette should preserve the draft and answer.

The native React APIs on this page are experimental, private source-build packages. Run the repository example to use them; they are not an npm installation recipe.

## Scope the theme to the conversation root

The example applies one of four classes around the native chat components. Those classes supply CSS tokens while `MessageList`, Markdown, and `ChatInput` continue reading the same owner. Keep the theme selection outside the session creation path; the code below makes a palette change a normal local React update.

~~~tsx
import { useState, type ReactNode } from 'react';

export function ThemeScope({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState('dark');
  return <section className={`trip-theme-${theme}`}>
    <select aria-label="Theme" value={theme} onChange={(event) => setTheme(event.target.value)}>
      <option value="dark">Dark</option><option value="light">Light</option>
    </select>
    {children}
  </section>;
}
~~~

The [React conversation walkthrough](/docs/react/langgraph/concepts/conversation-turns) connects this capability to requests, tools, UI state, and saved history.

## Four local palettes

Choose **Run** and select **Dark**, **Light**, **Ocean** or **Forest**. The palette changes a class on this chat root. It preserves the same application owner, exact unsent draft, messages and active conversation during streaming and saved-history confirmation. Palette changes make no runtime requests, cancel no work and do not change the document theme. A second chat root can choose independently; reload restores Dark.

The eight React chat CSS tokens are **--tp-chat-text**, **--tp-chat-muted**, **--tp-chat-border**, **--tp-chat-surface**, **--tp-chat-accent**, **--tp-chat-on-accent**, **--tp-chat-danger** and **--tp-chat-gap**. These local presets demonstrate this composed React surface.

## Reuse an Angular chat theme

React chat also reads the Angular chat token names. A stylesheet that sets `--tplane-chat-*` properties on `:root` restyles React chat the same way it restyles Angular chat, so one theme serves both frameworks. Each React token reads its Angular name first and falls back to its own default, and a `--tp-chat-*` value set on a chat root still wins over the shared theme.

| Angular token | React token or use |
| --- | --- |
| `--tplane-chat-text`, `--tplane-chat-text-muted`, `--tplane-chat-separator` | `--tp-chat-text`, `--tp-chat-muted`, `--tp-chat-border` |
| `--tplane-chat-bg`, `--tplane-chat-surface`, `--tplane-chat-surface-alt` | `--tp-chat-bg`, `--tp-chat-surface`, `--tp-chat-surface-alt` |
| `--tplane-chat-primary`, `--tplane-chat-on-primary` | `--tp-chat-accent`, `--tp-chat-on-accent`, and the user bubble (`--tp-chat-user-bg`, `--tp-chat-user-text`) |
| `--tplane-chat-error-text` | `--tp-chat-danger` |
| `--tplane-chat-error-*`, `--tplane-chat-warning-*`, `--tplane-chat-success-*` | Status panels, approvals and subagent status labels |
| `--tplane-chat-destructive`, `--tplane-chat-on-destructive` | The destructive approval action |
| `--tplane-chat-focus-ring` | Every focus ring, including A2UI controls |
| `--tplane-chat-elevation-float`, `--tplane-chat-scrim` | Menus, dialogs, the launcher, the debug panel, and dialog backdrops |
| `--tplane-chat-motion-duration`, `--tplane-chat-motion-ease` | Transitions |
| `--tplane-chat-font-*`, `--tplane-chat-line-height*`, `--tplane-chat-radius-*`, `--tplane-chat-max-width` | Typography, corner radii and the reading width |
| `--tplane-chat-citation-type-*-fg` | Source type colors for files, apps and memory |

React chat does not inject the Angular default values, so a token that the theme does not set keeps the React default. React follows `color-scheme` for light and dark defaults. Like Angular chat, it also follows a `data-theme="light|dark"` or `data-threadplane-chat-theme="light|dark"` attribute on the chat or any ancestor, so an app theme toggle reaches the chat with no extra code. The nearest attribute wins, and either attribute beats the system `prefers-color-scheme` setting. An explicit `--tp-chat-color-scheme` on a chat root beats both. The A2UI surface stylesheet reads the same attributes. A theme that switches with `[data-theme="dark"]` must set its dark values under that selector, as it does for Angular.

## Ask and continue

Only **Send** creates a confirmed server thread and starts the existing aviation graph. Ask an aviation question, then wait for **Response saved** before following up in the same conversation. Saved history must retain the exact confirmed prefix and current question/answer identities; streamed text alone cannot authorize continuation. Theme selection remains available while the owner is busy.

**New conversation** clears local state and creates nothing until Send. **Stop** revokes active delivery; stopped, failed or uncertain work requires a new conversation without automatic retry or replay. Cleanup failure permanently disables authoring and requires reload. These browser ownership checks do not claim a durable external store or backend cancellation acknowledgment.

## Build from source

~~~sh
npx nx build cockpit-chat-theming-react
npx nx e2e cockpit-chat-theming-react
~~~

The isolated build consumes installed candidate packages. Local browser tests exercise actual SDK HTTP and SSE from the compiled Python graph with deterministic providers; they do not prove live provider execution. Docs, Code and Run use the same React implementation and preserve the mounted iframe and draft across mode navigation. Angular remains the default, with its own components and tokens.
