# React chat threads preview

Give each trip its own conversation and draft. Switching from Portland to another destination should load that thread without sending a new question or overwriting the draft left in the first conversation.

The native React APIs on this page are experimental, private source-build packages. Run the repository example to use them; they are not an npm installation recipe.

## Select an identity before allowing commands

The application holds a page-local collection of confirmed IDs and drafts. Selecting an ID creates a session bound to that conversation and loads saved history; only then can the user continue. The sidebar lists the conversations saved on the server, but titles are display metadata, not identifiers or proof that a conversation is ready. This example teaches thread selection without URL routing.

The [React conversation walkthrough](/docs/react/langgraph/concepts/conversation-turns) connects this capability to requests, tools, UI state, and saved history.

## Create and switch conversations

Choose **Run**, select **Try a question**, then send the draft. The suggestion only fills the composer. The first Send creates a conversation; **New conversation** opens a blank local view and waits for Send before creating another.

The connected `ThreadSidebar` lists the server's conversations from a directory built with `createLangGraphThreadDirectory`. Its row menus rename, pin, reorder, archive, delete and move conversations into projects, and project names are kept in the LangGraph Store. Select a conversation created on this page to restore its messages and draft. Each selection loads its saved history before another message can be sent. New preserves drafts on saved conversations and replaces an unsent blank view.

## Connected sidebar

`ThreadSidebar` comes from `@threadplane/react/chat` and draws New chat, Projects, Recent and Archived for any `ThreadDirectory`. `createLangGraphThreadDirectory` from `@threadplane/langgraph` builds one over the LangGraph threads API. The directory belongs to the application: the sidebar subscribes to it but never disposes it, so dispose it yourself when the page unmounts.

Create the directory and dispose it in the same effect. A directory created in `useState` and disposed in an effect cleanup does not survive React StrictMode: the development double mount runs the cleanup once, and the directory stays disposed for good. The example creates its directory this way.

~~~tsx
import { useEffect, useState } from 'react';
import { Client } from '@langchain/langgraph-sdk';
import type { AgentSession, ThreadDirectory } from '@threadplane/core';
import { createLangGraphThreadDirectory } from '@threadplane/langgraph';
import { ThreadSidebar } from '@threadplane/react/chat';

export function Conversations(props: {
  readonly apiUrl: string;
  /** The selected conversation's session, for example from `createSession`. */
  readonly session?: AgentSession;
  readonly threadId: string | null;
  readonly onThreadChange: (threadId: string | null) => void;
}) {
  const { apiUrl, session, threadId, onThreadChange } = props;
  const [directory, setDirectory] = useState<ThreadDirectory | null>(null);
  const [projectId, setProjectId] = useState<string | null>(null);
  useEffect(() => {
    const created = createLangGraphThreadDirectory({
      client: new Client({ apiUrl, callerOptions: { maxRetries: 0 } }),
    });
    setDirectory(created);
    return () => created.dispose();
  }, [apiUrl]);
  if (!directory) return null;
  return (
    <ThreadSidebar
      directory={directory}
      session={session}
      activeThreadId={threadId}
      onSelect={onThreadChange}
      onActiveRemoved={() => onThreadChange(null)}
      selectedProjectId={projectId}
      onProjectSelect={(id) =>
        setProjectId((current) => (current === id ? null : id))
      }
    />
  );
}
~~~

The `session` is the `AgentSession` of the selected conversation, such as one returned by `createSession` from `@threadplane/langgraph` for that thread. The example builds a session the same way each time a conversation is selected.

With no `onNewChat`, New chat creates a thread through the directory and passes its identifier to `onSelect`. Pass `onNewChat` to replace that behavior, as the example does to open a blank local conversation.

### Projects

Project names are stored in the LangGraph Store under the namespace `['threadplane', 'projects']`. Each project is one item whose key is the project identifier and whose value is `{ name }`. A thread joins a project through its `projectId` metadata. Pass `projects: false` to `createLangGraphThreadDirectory` to turn projects off, or pass your own project store in the same option. A server without the Store API still lists threads: the snapshot carries no `projects`, the sidebar hides the Projects section and project commands fail without affecting the thread list.

`selectedProjectId` is controlled by the application. When it holds a project identifier, Recent and Archived list only that project's conversations; `null` or no value lists every conversation. `onProjectSelect` reports the project the user picked, so the snippet above clears the selection when the selected project is picked again.

### Refreshing after a run

The sidebar loads the directory when it mounts and again after each row command. Pass `session` and it also refreshes every time a run ends, which is when the graph has written a generated title. Any object with `getSnapshot` and `subscribe`, such as an `AgentSession`, works.

### The active thread

The sidebar never owns the selection. Pass `activeThreadId` to highlight a row and handle `onSelect` to switch. When the user deletes the conversation that is active, the sidebar calls `onActiveRemoved` after the delete succeeds, so the application can return to a new chat instead of keeping a dangling selection.

### Four levels of customization

1. **Features and labels.** The `features` prop turns built-in behavior off: `projects`, `archive`, `pin`, `reorder`, `rename` and `remove`. Each defaults to on when the directory supports it. The `labels` prop replaces text for `newChat`, `projects`, `recent`, `archived`, `archivedEmpty`, `loadError`, `retry` and `empty`.
2. **Slots.** `renderThread` replaces each conversation row, `extraActions` appends application commands to each row menu, and `before` and `after` place content around the built-in sections. Rows drawn by `renderThread` get no row menu.
3. **Your own directory.** `directory` accepts any object that meets `ThreadDirectory`, so an application without a LangGraph server can supply its own list and commands. The sidebar offers a command only when the directory implements it.
4. **Lower-level pieces.** `ThreadList`, `ProjectList` and `ChatSidenav` remain public for applications that want full control over layout and behavior.

## Keep titles optional

Titles come from thread metadata, which the graph writes after the first turn. The sidebar shows them as literal text and shows "Untitled conversation" when a title is missing or invalid. A title never authorizes execution or replaces saved-history validation.

## Check saved history before continuing

After each successful stream, the application reads saved history and compares it with the observed messages. Selection creates a fresh session fixed to the selected thread identity and checks the exact saved transcript and root checkpoint retained for that conversation. Follow-up messages must extend the confirmed prefix with one user message and one completed assistant answer.

## Stop and recover

While creating, receiving or loading, **Stop** releases the current owner and prevents late responses from restoring its commands. An uncertain conversation is marked unavailable, and selecting it shows a notice instead of loading it. Other confirmed conversations remain selectable, and **New conversation** can start a separate one after cleanup. There is no retry, replay or resume of uncertain work.

Text typed during streaming or saved-history confirmation is kept as the next draft. Selection and cleanup temporarily disable typing. Switching back to a confirmed conversation restores its own draft.

## Build from source

From a Threadplane checkout with dependencies installed:

~~~sh
npx nx build cockpit-chat-threads-react
npx nx e2e cockpit-chat-threads-react
~~~

The isolated build installs private candidate packages. Browser tests use the real SDK and compiled Python graph with deterministic providers and real saved checkpoints. Test workers and verification endpoints are excluded from public output. Background title generation updates metadata without entering the answer stream. This preview does not claim URL routing or server-side search.
