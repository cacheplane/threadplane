# React chat threads preview

Give each trip its own conversation and draft. Switching from Portland to another destination should load that thread without sending a new question or overwriting the draft left in the first conversation.

The native React APIs on this page are experimental, private source-build packages. Run the repository example to use them; they are not an npm installation recipe.

## Select an identity before allowing commands

The application holds a page-local collection of confirmed IDs and drafts. Selecting an ID creates a session bound to that conversation and loads saved history; only then can the user continue. The sidebar lists the conversations saved on the server, but titles are display metadata, not identifiers or proof that a conversation is ready. This example teaches thread selection without URL routing.

The [React conversation walkthrough](/docs/react/langgraph/concepts/conversation-turns) connects this capability to requests, tools, UI state, and saved history.

## Create and switch conversations

Choose **Run**, select **Try a question**, then send the draft. The suggestion only fills the composer. The first Send creates a conversation; **New conversation** opens a blank local view and waits for Send before creating another.

The connected `ThreadSidebar` lists the server's conversations from a directory built with `createLangGraphThreadDirectory`. Its row menus rename, pin, reorder, archive, delete and move conversations into projects, and project names are kept in the LangGraph Store. Select a conversation created on this page to restore its messages and draft. Each selection loads its saved history before another message can be sent. New preserves drafts on saved conversations and replaces an unsent blank view.

## Keep titles optional

Titles come from thread metadata, which the graph writes after the first turn. The sidebar shows them as literal text and shows "Untitled conversation" when a title is missing or invalid. A title never authorizes execution or replaces saved-history validation.

## Check saved history before continuing

After each successful stream, the application reads saved history and compares it with the observed messages. Selection creates a fresh session fixed to the selected thread identity and checks the exact saved transcript and root checkpoint retained for that conversation. Follow-up messages must extend the confirmed prefix with one user message and one completed assistant answer.

## Stop and recover

While creating, receiving or loading, **Stop** releases the current owner and prevents late responses from restoring its commands. An uncertain conversation is marked unavailable, and selecting it shows a notice instead of loading it. Other confirmed conversations remain selectable, and **New conversation** can start a separate one after cleanup. There is no retry, replay or resume of uncertain work.

Text typed during streaming or saved-history confirmation is kept as the next draft. Selection and cleanup temporarily disable typing. Switching back to a confirmed conversation restores its own draft.

## Build from source

From a Threadplane checkout with dependencies installed:

~~~sh
npx nx build cockpit-chat-threads-react
npx nx e2e cockpit-chat-threads-react
~~~

The isolated build installs private candidate packages. Browser tests use the real SDK and compiled Python graph with deterministic providers and real saved checkpoints. Test workers and verification endpoints are excluded from public output. Background title generation updates metadata without entering the answer stream. This preview does not claim URL routing or server-side search.
