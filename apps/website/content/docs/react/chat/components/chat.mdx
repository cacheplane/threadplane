# Chat

`Chat` from `@threadplane/react/chat` combines `MessageList`, a waiting indicator, a session error alert, and `ChatInput` for a core `AgentSession`. It borrows that session; the application retains command and lifetime authority.

This is an experimental, private source-build component. See [chat setup](/docs/react/chat/getting-started/installation).

## Supply the session and presentation

In a private source-build client application, pass an existing owner:

~~~tsx
import type { AgentSession } from '@threadplane/core';
import { Chat } from '@threadplane/react/chat';
import '@threadplane/react/chat/styles.css';

export function Conversation({ session }: { readonly session: AgentSession }) {
  return (
    <Chat
      session={session}
      label="Trip message"
      placeholder="Ask about your trip…"
    />
  );
}
~~~

| Prop                                            | Purpose                                                |
| ----------------------------------------------- | ------------------------------------------------------ |
| `session`                                       | Required app-owned core session.                       |
| `content`                                       | Optional app-owned `MessageContent` projection.        |
| `renderMessage`                                 | Stable callback replacing default row presentation.    |
| `label`, `placeholder`, `hint`, `submitOnEnter` | Composer presentation and input behavior.              |
| `disabled`                                      | Turns the composer off while your application cannot accept a message. Stop stays available. |
| `className`                                     | Additional root styling.                               |
| `onRetry`                                       | Optional application-owned zero-argument retry intent. |
| `typingIndicator`                               | The waiting indicator in the transcript: `false` hides it, `{ label, announce }` changes its words or silences its announcement. |

Import `@threadplane/react/chat/styles.css` explicitly. The component observes the session, shows its current error message, treats `status === 'running'` as busy, submits trimmed text, and forwards Stop.

`renderMessage` uses `MessageListProps['renderMessage']` and forwards `(row, context)` unchanged. The exported readonly `MessageListRowContext.current` is true only for the final supplied row. Its optional readonly `prevRole` is the immediately preceding supplied projected row's role (`rows[index - 1]?.role`), undefined for the first row. One-argument callbacks remain compatible. A custom renderer owns its presentation, including forwarding `prevRole`, `current` and delivery-derived `streaming` to [ChatMessage](/docs/react/chat/components/chat-message). Default rows show a caret only for a current streaming assistant; all complete delivery outcomes remove it. Explicit previous-role context supports assistant-to-user spacing through wrappers; existing assistant `:first-child` spacing remains DOM-dependent. Full T23 parity remains open.

The default [TypingIndicator](/docs/react/chat/components/typing-indicator) uses the same snapshot and subscription. It shows while running with no messages, a last user message, or an empty last assistant message; it hides on the first assistant text, including whitespace, or a last tool/system message. The polite status label follows the last row inside the scrolling transcript, so it stays in view while the list is pinned, and appears before error/composer. Pass `typingIndicator={{ announce: false }}` when your application already announces submission progress, such as a status in `inputFooter`, so the run is not read twice.

When the reader scrolls upward, [ScrollBubble](/docs/react/chat/components/scroll-bubble) offers **Scroll to latest**. Its mode comes from the same snapshot status. Only an explicit activation scrolls and focuses the transcript; the existing MessageList remains the scroll owner. Token growth while unpinned preserves reader position and focus. No new Chat props, session reads, or subscriptions are required.

It does not dispose the session. If you supply `content`, it also remains yours to dispose. Without supplied content, Chat manages its own message projection. Replacing the session resets the keyed composer.

## Choose explicit composition for application policy

Chat catches command promise rejections; [ChatError](/docs/react/chat/components/chat-error) displays the classified `snapshot.error` message and detail. Supported session `checkStatus` is forwarded with the session receiver and a latest-error identity guard. Optional `onRetry` forwards your explicit retry intent; Chat never replays a submission. A check without capability never falls through to retry, and explicit `none` offers no action. Your callback owns its async results and lifetime. Chat does not provide saved-history confirmation or an application-level `canSubmit` prop.

If continuation requires more evidence than session status, use `MessageList` and `ChatInput` around your own facade. The [chat quickstart](/docs/react/chat/getting-started/quickstart) follows that approach.

A native AG-UI snapshot is not automatically a core `AgentSession` snapshot. Use its [supported projection](/docs/react/ag-ui/concepts/architecture) instead of passing an incompatible session to Chat.

See [MessageList](/docs/react/chat/components/chat-message-list) for custom rows and [Lifecycle](/docs/react/chat/guides/lifecycle) for owner cleanup.
