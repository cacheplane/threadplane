# MessageList

`MessageList` renders readonly `MessageRow` values prepared by an application-owned content projection. It does not subscribe, submit, parse session events, or dispose the projection.

This component belongs to the experimental, private React source-build package.

## Prepare rows before rendering

The [messages example](/docs/react/chat/concepts/message-model) projects session observations in its application owner, then publishes `rows`. React reads that snapshot and passes the rows to `MessageList`.

Each row keeps a stable `id`, role, original message, Markdown snapshot, and associated tool observations. Preserve unique IDs and immutable row references so keyed, memoized rows can retain their presentation between updates.

## Choose default or custom presentation

This private source-build view borrows already prepared rows:

~~~tsx
import type { MessageRow } from '@threadplane/content/messages';
import { MessageList } from '@threadplane/react/chat';

export function Transcript({ rows }: { readonly rows: readonly MessageRow[] }) {
  return <MessageList rows={rows} label="Trip conversation" />;
}
~~~

The default renderer displays role labels, Markdown, assistant reasoning, resolved sources, and tool observations. Tool-role message content remains literal text. A stable `renderMessage(row)` callback replaces that entire presentation; it must explicitly include anything you want to retain.

Default assistant rows pass their provider citations to inline Markdown references and merge Sources with the same accepted Markdown snapshot. Whole provider records win exact-ID collisions, including missing or blocked URLs; Markdown-only sources are included. Combined Sources use stable ascending index order. Metadata-only corrections update both views while preserving unchanged Markdown snapshots.

Provider metadata is supplied only to assistant rows. User and system rows retain their own Markdown definitions, and tool content stays literal. Default citation links use the shared destination policy; inline previews remain an explicit choice in a custom renderer.

Define the callback outside rendering or stabilize it with `useCallback`. Put hooks in a component returned by the callback. Recreating the callback on every token defeats row memoization.

Optional `children` appear after the rows inside the same scrolling region, useful for application-owned approval controls. `label` names the region and defaults to “Conversation”; `className` customizes its root.

## Respect the reader's position

The list follows updates while pinned at the bottom. Scrolling upward releases that pin; returning within 32 pixels of the bottom restores it. Resize observation follows content growth, including later layout changes, while pinned.

Give the list a constrained height through the surrounding layout and import the chat stylesheet. The component owns scrolling presentation only. It does not mark a response successful, authorize a tool, or load older history.

Optional `renderScrollControl(controls)` renders a sibling after the unchanged region. The readonly controls expose `pinned`, `scrollToLatest()` and `focus()`; attach them to explicit event handlers. The first restores pinned following and directly scrolls to the bottom, and the second focuses the current region with `preventScroll: true`. Context identity stays stable while pinned stays unchanged, and retained methods are inert before commit and after unmount. See [ScrollBubble](/docs/react/chat/components/scroll-bubble) for a compiled composition example. The callback never enters memoized row props or changes row inference.

See [Reasoning](/docs/react/chat/components/chat-reasoning) and [Markdown](/docs/react/chat/guides/markdown) for the borrowed content views.
